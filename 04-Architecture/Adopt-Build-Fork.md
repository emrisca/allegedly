## 3. Mandatory Written Justifications for Every `Build` Verdict

Per Allegedly's Adopt-First discipline, every **`Build`** entry in Section 1 is justified below by proving why no suitable FOSS candidate exists as of `2026-11-24`:

1. **`B1` — Synchronized Raw WebGL2 Order-Flow Layer (Footprint Bars, Liquidity Heatmap, TPO Profiles):**
   - *Why no FOSS exists:* Both verified Apache-2.0 JS charting engines (`Lightweight Charts v5.3.0`, `KLineChart v10.1.1`) are **Canvas2D-only** and stall below `60 fps` on `200k`-cell liquidity heatmaps or `5k`-cell footprint viewports (`R01`). `regl` is WebGL1-only (`R01-S22`). `PixiJS` (`v8.23.0`, MIT) imposes heavy scene-graph object overhead for volatile per-tick cell grids. `flowsurface-rs/flowsurface` (`wgpu`) is **`GPL-3.0-or-later`** and coupled to `iced`, not a WebView canvas. A thin raw WebGL2 instanced renderer + DPR glyph atlas (`~2–4k` LOC, validated in `S01`/`S04` & `ADR-0004`) is the minimum viable path to hit `60 fps` across macOS `WKWebView` and Windows `WebView2` while staying WebGL2-portable for post-`v1.0` Linux.
2. **`B2` — Clean-Room Drawing Suite, Magnet-Snap & `analysis.toml` Workspace Layer:**
   - *Why no FOSS exists:* TradingView `Lightweight Charts` intentionally ships **zero built-in drawing tools, magnet snapping, undo/redo stacks, or layer persistence** (`R01-S04`, `R01-S06`), while TradingView Advanced Charts (which has 110+ drawings) is proprietary/banned (`R01-S08`). `HQChart` is disqualified due to its conflicting Chinese User Agreement (`R01-S18`). Building Allegedly's clean-room drawing state model and `analysis.toml` / `workspace.toml` / `template.toml` persistence (`ADR-0010`) over LWC's `ISeriesPrimitive` hooks guarantees 100% Settings-as-Code compliance (`Constraints` #6) and zero vendor lock-in.
3. **`B3` — Fixed-Point `i64` Order-Flow Math, `16-ary` Segment-Tree Profiles & Bitmask TPO Core (`allegedly-orderflow`):**
   - *Why no FOSS exists:* No permissive (`Apache-2.0`/`MIT`) Rust crate provides fixed-point `i64` tick-indexed Footprint Bars, diagonal imbalances, **`16-ary` dyadic segment-tree** visible-range Volume Profiles (`S08`: `9.04 µs` VRVP, `ADR-0006`), `u128` bitmask TPO Profiles (split/merge/Initial Balance/Single Prints), and delta-ring-buffer L2 heatmaps with explicit `ProvenanceHeader` tracking (`R05`). The only comparable Rust implementation (`flowsurface-data`) is **`GPL-3.0-or-later`** and coupled to `iced_core` (`R08-S01`).
4. **`B4` — Provider-Agnostic Market-Data Normalizer & Provenance Engine (`allegedly-ingest`):**
   - *Why no FOSS exists:* Existing multi-venue data frameworks either fail the lightweight Rust core constraint (`OpenBB` is Python; `Hummingbot` is Python; `QuantConnect/Lean` is C#/.NET), carry copyleft (`nautilus_trader` is `LGPL-3.0-only`), or lack 5-tier loud provenance stamping (`EXACT: L3-MBO` through `SYNTHETIC: 1m-INTRABAR`), Coinbase maker→taker inversion, fail-closed `BookState::Stale` recovery, and US-safe crypto/CME normalization (`barter-data` is crypto-focused). Building thin Rust normalizers over adopted `tokio`/`reqwest`/`databento::dbn` crates (`S05`, `ADR-0008`) enforces `Constraints` #7 & #8 directly at the ingest boundary.
5. **`B5` — Fixed-Point Order Management System (OMS), Risk Kill-Switch & Local Paper Simulator (`allegedly-oms`):**
   - *Why no FOSS exists:* Safety-critical desktop execution requires strict zero-float `PriceTicks(i64)`, SQLite WAL write-ahead order intent logging, `client_order_id` idempotency across reconnects, 12-state `OrderState` reconciliation, atomic 4-step Kill-Switch / Flatten-All with Risk-Reduction Bypass during `BookState::Stale`/`RECONCILING`, Sim-vs-Live host/keychain isolation, and prop-firm anti-hedging guards (`R04`, `S06`, `ADR-0009`). `nautilus_trader` is `LGPL-3.0-only` (unsuitable for static Rust core linking); `barter-rs` lacks desktop OMS WAL, OCO/auto-bracket templates, and multi-asset futures/equities semantics; `StockSharp` is proprietary (`R08-S10`). We adopt `barter-rs` / `rust-ibapi` strictly as replaceable in-process `BrokerAdapter`s beneath our clean-room `allegedly-oms`.
6. **`B6` — Deterministic Study Engine (`allegedly-studies`), L1/L2/L3 Replay Simulator (`allegedly-replay`), & Staged Clean-Room Pine-Inspired DSL Front-End (`v0.4+`):**
   - *Why no FOSS exists (`Study` Engine & Pine DSL — `B6a`):* Every mature Pine v5/v6 parser/runtime verified on `2026-11-24` is either license-incompatible (`PineTS` `AGPL-3.0`, `OpenPineScript` `GPL-3.0`, `pynescript` `LGPL-3.0`, `pineforge-codegen-oss` non-FOSS `PineForge Source License 1.2`), closed-source SaaS (`PyneComp`), or bound to TradingView's proprietary `PineJS` (`pine-transpiler`), while `ferranbt/pinecone` (`MPL-2.0`, 29★) is early v4/v5-only (`R06`). Per `S07` and `ADR-0005`, we adopt **`Wasmtime v51.0.0`** (`Apache-2.0 WITH LLVM-exception`) + **`Luau` via `mlua v0.12.3`** (`MIT`; **`Rhai` rejected** on `~10×` slower throughput and solo bus factor) + **`TA-Lib v0.8.3`** (CI parity oracle) and build only the lean pure-Rust O(1) `Study` state machine (`v0.1`) and staged clean-room Pine-inspired front-end (`v0.4+`).
   - *Why no FOSS exists (Replay/Backtest — `B6b`):* Every popular Python backtester is disqualified (`vectorbt` Commons Clause, `backtrader` & `pysystemtrade` GPL-3.0) or daily-equity-only (`zipline-reloaded`), and `nautilus_trader` is `LGPL-3.0-only` (adopted only as an external sidecar). Building a lean pure-Rust `allegedly-replay` sharing `allegedly-studies` and `allegedly-orderflow` (informed by MIT `nkaz001/hftbacktest` queue math, `ADR-0007`) guarantees 100% bit-identical live/replay determinism inside `< 40 MB`.
